# Fiji VR 0.12

View grayscale or RGB images and Z stacks in a browser, VR, or supported passthrough AR. Target headsets: Meta Quest 3 and PC VR with a WebXR-compatible browser/runtime. This is a prototype; hardware testing is still required.

## Install once

1. Quit Fiji and remove the previous Fiji VR JAR from its `plugins` folder.
2. Copy [fiji-vr-0.12.0.jar](https://github.com/WagnerJon/fiji-vr/raw/refs/heads/main/dist/fiji-vr-0.12.0.jar) into that folder.
3. Start Fiji.

No terminal, Python, Maven, development Java installation, or manually configured server is required to use the plugin. Fiji provides its own Java runtime.

## View an image

1. Open an RGB image/stack or grayscale image/stack in Fiji. 4D stacks must have their Z slices and time frames correctly assigned in Fiji; the plugin uses those dimensions and does not guess time from an unlabelled stack.
2. Choose **Plugins → Fiji VR → View in VR / AR**.
3. The plugin prepares the image at original spatial resolution and opens the desktop viewer automatically.
4. For Quest or another standalone headset, click **Connect headset**. The first connection installs a verified helper automatically, then creates and checks an HTTPS link. The window displays a copyable URL and QR code. Open the link in the headset's browser. On the same local network, choose **Use local Wi-Fi**, approve local-network access if asked, and wait for **Local Wi-Fi** before choosing **Enter VR** / **Enter AR**. Previously granted access reconnects automatically. The viewer clearly labels **Internet relay** if direct transfer is unavailable. Scanning a QR on a phone opens the phone browser; transferring that URL to the headset is separate.
5. Keep the plugin window open. **Stop sharing** closes the local-network listeners and ends relay access while retaining desktop viewing; closing the window stops the server and deletes its temporary image copy.

A connected PC VR headset may work directly with the local desktop viewer in a WebXR browser using its active XR runtime. Standalone Quest uses the HTTPS link. Neither terminal commands nor certificate installation are needed.

## Connection and privacy

Desktop mode runs on loopback and serves bundled viewer libraries; no image traffic is sent to an external service. The first click on **Connect headset** downloads a pinned official Cloudflare connection helper and verifies its SHA-256 against release metadata embedded in the plugin. On macOS the cache is under `~/Library/Application Support/Fiji VR/Connection`. Intel and Apple Silicon Macs are supported; Linux x64/ARM64 and Windows x64 helper definitions are also included but untested.

Headset sharing uses a temporary Cloudflare Quick Tunnel for the trusted HTTPS viewer, metadata and local-connection discovery. The headset may then read image byte ranges directly from Fiji over your local network. **Local Wi-Fi** means image chunks bypass Cloudflare; **Internet relay** means they pass through Cloudflare. Direct image transfer uses HTTP on your local network and is not encrypted there; the top-level viewer remains on HTTPS so WebXR can remain available. Use a trusted local network for that option. A random session token protects the viewer path: anyone with the full URL can view it while sharing is active. This is a bearer link, not account authentication or end-to-end encryption against the relay. Sharing starts only when clicked, with that behavior explained in the window. No analytics or external viewer scripts are loaded. Closing the session invalidates access but cannot erase data already loaded in a client's browser.

Internet access and access to GitHub/Cloudflare are required for standalone-headset sharing. Quick Tunnels have no uptime guarantee; DNS/routing can delay connection, and the UI checks reachability before showing the QR code. Network failure offers retry and leaves desktop viewing available. There is no certificate-warning bypass or change to browser security flags. Local HTTP image requests use the browser’s supported Local Network Access permission and standard CORS; the headset viewer page remains on trusted HTTPS. Cloudflare is appropriate for this prototype; a controlled, authenticated relay is a future production option.

## Direct local image transfer

Connect the Fiji computer and headset to the same LAN (a wired computer on the same router also works). The plugin opens random-port image listeners on up to four active private IPv4 interfaces only while headset sharing is enabled. It excludes loopback, point-to-point and virtual interfaces during normal discovery; no router port forwarding, certificates, commands, extra app or additional browser tab are needed. If macOS or a firewall asks whether Fiji/Java can access the local network, allow it for this connection. Guest Wi-Fi and client isolation can prevent devices from communicating even when the Wi-Fi name matches.

The HTTPS viewer receives the session's exact local endpoints, then checks Local Network Access permission. Previously granted permission for the same HTTPS link can connect automatically (a new temporary link may ask again); otherwise the first local attempt waits for **Use local Wi-Fi**, so a permission prompt is tied to that button. The first reachable endpoint must identify the same session. The browser sends native full-resolution image chunks and slice ranges directly to that endpoint, without cookies or credentials; local chunks skip gzip work. Transfers keep the existing small-piece size/identity validation, cancellation and retries. A network failure or incomplete local body switches the affected piece to HTTPS relay and updates the route readout. **Use internet relay** is available to switch back manually. Changing routes restarts an in-progress selected-volume load, or restarts pending background preparation while retaining already cached volumes; playback, channels, original pixels and transforms remain intact.

Local listeners enforce the same random session-token path and resource/file allowlist, reject unrelated browser origins and non-private clients, and return CORS headers only for the current HTTPS headset origin and local desktop viewer. The HTTPS page's CSP permits only the exact local listener origins. Local endpoints disappear when sharing stops or the plugin window closes; the ordinary desktop server remains loopback-only. This is not account-based authentication, and anyone holding a live viewer link can already read the session through its relay.

**Browser compatibility matters:** HTTPS-to-local-HTTP requests require support for Local Network Access's permission-gated mixed-content exemption. The implementation marks requests with `targetAddressSpace: 'local'`; older headset/browser builds can still reject them, in which case the readout stays Internet relay. Do not bypass security warnings or change browser flags. Supporting browser behavior is documented in the [Chrome Local Network Access guide](https://developer.chrome.com/docs/modern-web-guidance/guides/security/local-network-access). Quest hardware compatibility and actual Wi-Fi throughput still require a headset check. Internet is still needed for the initial HTTPS link/QR, viewer assets and metadata; this is not a completely offline headset app.

## Loading speed and generated-link reliability

ImageJ’s usual image window displays a single local 2D slice. A full-volume viewer must transfer the selected channel/time volume to a second device, upload it to that device’s GPU, and sample the 3D data along viewing rays for both eyes. For example, a 2048 × 2048 × 100 uint8 volume contains 400 MiB before block-border overhead, compared with 4 MiB for a single slice. RAM capacity helps hold that data but does not provide network bandwidth or desktop-GPU rendering performance. The generated HTTPS link opens through Cloudflare. In Internet relay mode its image traffic also uses the internet, even when both devices are on the same Wi-Fi. Local Wi-Fi routes those image bytes directly and avoids that relay bottleneck. This does not establish a fixed Cloudflare rate cap or guarantee a particular Wi-Fi speed.

A regression test reproduced the previous response failure on the public link: a 64 MiB response advertised its full length but ended after 50,839,543 bytes. This identifies a real truncated-transfer condition; it does not prove which network/proxy hop terminated that particular response. The updated protocol separates network pieces from GPU texture blocks. Each network piece is at most 2 MiB, with up to three requests in parallel. Failed, truncated, incorrectly identified or transient-error responses are retried up to three times, and cancellation stops pending retries. Each completed piece is checked for its exact decoded size and byte-range identity before being assembled into the original GPU block.

Where the browser supports gzip decompression, the plugin compresses each piece losslessly and uses the compressed form only when it is smaller. No pixel resampling or image-quality reduction is involved. The response explicitly identifies its coding and original byte range; gzip is an application payload rather than a proxy-controlled content transformation. Browsers without that API use checked HTTP byte ranges. The origin returns precise response lengths, closes completed bodies explicitly, and sends `Cache-Control: no-transform` to prevent relay transformations. Static viewer resources now also have known response lengths. The UI distinguishes decoded image progress from network throughput and reports actual transfer size on completion.

Maximum-intensity rendering no longer evaluates the transparent compositing math at every sample. Both rendering modes can stop a ray once its result is mathematically saturated, without changing the spatial sampling. These changes improve robustness and some loading/rendering costs; they do not establish parity with ImageJ’s local slice-window responsiveness. Native Quest performance still requires hardware testing.

## Renderer acceleration and profiling

The renderer prepares a small conservative maximum grid alongside each full-resolution volume. Cells span 32 × 32 × 8 native voxels (Z cells grow only if needed to fit the device’s acceleration texture). Each cell includes the one-voxel interpolation neighborhood on all sides, including across texture blocks. For RGB, maxima consider RGB components, not the always-opaque alpha byte. The grid is auxiliary metadata; the original source texture blocks and native ray spacing are unchanged.

When a cell cannot contribute above the threshold, the shader advances to the next cell boundary on the original sample lattice. In maximum-intensity mode, cells whose conservative bound cannot improve the current peak can also be skipped. The boundary calculation leaves an extra sample rather than jumping past an unbounded point. Transparent mode skips only zero-contribution regions and retains the original compositing calculation. Preparing the grid runs in a reusable module worker, with transferred buffers returned for GPU upload; it does not scan the large volume on the interaction thread in supported browsers.

The desktop renderer redraws when camera, volume, C/Z/T, display parameters or size change, rather than continuously ray-marching an idle image. Visible VR/AR continues to render every XR frame so head motion stays tracked; hidden pages and hidden XR sessions do not keep drawing the volume. Playback also continues rendering. Loading and DOM progress updates do not require rerendering an unchanged volume.

**Skip empty / hidden regions** toggles conservative skipping. **Measure renderer speed** pauses playback and compares traversal on/off using the same camera, original voxels and ray spacing. It reads back both images and checks byte equality. It uses disjoint GPU timer queries where available; otherwise it reports frame-plus-readback completion time, not draw-submission time or an FPS estimate. The benchmark warms both paths and reports five-sample medians. On a rotated synthetic 2048 × 2048 × 40 desktop test, the 32 × 32 × 8 grid reduced the measured GPU median from 83.4 ms to 32.5 ms (2.57×), with an identical rendered-pixel comparison. In transparent mode, a rotated test measured 134.8 ms native versus 40.2 ms accelerated (3.35×), also with identical rendered pixels. A finer 16 × 16 XY grid was also evaluated and did not improve that test, so it was not chosen as the default. These are view-, data- and hardware-specific measurements, not Quest frame-rate guarantees. It selects the faster path only if the pixel comparison is identical. Readback-based times include transfer-to-CPU overhead and are suitable for a controlled local comparison, not a universal headset performance claim. Run outside immersive mode after loading, and repeat after rotating or changing render mode to profile that view. Dense data may benefit less or favor native traversal.

## Original-resolution rendering

The default command preserves spatial dimensions, including 2048 × 2048 images and one-pixel-wide features. Single images open in slice view. Desktop rendering uses the display’s device pixel ratio rather than a 1.5× cap. The image is still projected into the window/headset display, so zooming or moving closer is needed to inspect pixels in detail; fitting an image into a small view is different from deleting source pixels.

The default is **full-volume rendering at original spatial resolution**, with **Volume memory → Unlimited**. There is no automatic 128 MiB cutoff, no fixed 4096-voxel ray-step cap, and no automatic switch to individual slices. “Unlimited” means that the viewer does not impose a memory budget; it does not remove the browser/GPU’s physical limits. The optional 512 MiB / 1 GiB / 2 GiB selections impose an explicit budget. Exceeding a chosen budget or a hard texture limit reports an error instead of changing the image representation.

A volume is partitioned into contiguous native-resolution Z blocks and loaded using HTTP byte ranges. Every block keeps the full original XY pixel grid. One neighboring plane is included on each interior side so linear interpolation remains continuous across block boundaries. A single ray marcher samples the entire collection together for correct full-volume maximum intensity or transparent compositing; it is not showing independent slice planes or downsampled blocks. The ray step count follows the voxel grid dynamically rather than stopping at 192 or 4096 steps.

Blocks are assembled from small losslessly transferred pieces and uploaded one at a time. CPU staging buffers are released after each GPU upload; the complete selected channel/time volume stays resident on the GPU. The selected volume stays resident, with nearby time points retained in the playback cache. The cache defaults to 512 MiB of **extra** graphics memory, separate from the displayed volume and the Volume memory setting. The cache size counts native texture blocks (including borders) and the acceleration grid. The displayed volume is protected from eviction. During a foreground replacement, memory can additionally include an incoming volume; CPU staging holds one block. Disable Playback cache to retain only the displayed volume and an incoming replacement. Cancelled and stale loads release their staging GPU resources and cannot replace the newer selection. This is not out-of-core rendering of an arbitrarily large volume with one tiny GPU buffer.

Hard limits remain: each native XY plane must fit the device’s 3D texture XY dimensions, each block depth must fit its 3D limit, and the block count plus one acceleration texture must fit the fragment shader’s texture-unit count. A standalone Quest/browser can still exhaust graphics memory or hit a graphics watchdog even though the headset has 8 GB total RAM. Such a failure is reported, with no reduction or slice fallback. The sidebar reports block count, estimated GPU data size (including border overlap) and the memory setting. Reopening the session is required after graphics-context loss because CPU copies of uploaded blocks are deliberately released.

**Use full-resolution slices** is an explicit alternative, and its **Show full-resolution volume** button returns to the normal renderer. That navigation resets the initial view. Slice-only mode within a normally loaded full volume remains an ordinary toggle on the desktop and headset panel. Outside slice-only mode, Z is shown as an outline only. The filled slice image is hidden, avoiding an overlay that could dim or cover rendered structures. Single images with one Z plane naturally remain flat.

## Rendering and controls

**Transparent volume is the default.** It composites samples from the viewer towards the back, with nearer samples contributing before farther samples. Opacity controls how strongly layers obscure those behind them. The optional **Brightest projection (MIP)** instead chooses the sample with the greatest intensity along each viewing ray, regardless of its depth: a brighter back layer can replace a dimmer front layer completely. This mode is useful for bright sparse signals but does not communicate occlusion like a solid object. Lower Signal threshold to retain weak structures; high thresholds deliberately remove them. The sidebar explains these differences and shows whether source Z clipping is active. These are display choices, with no source pixel reduction or changes to the Fiji image.

RGB is preserved as interleaved RGBA8 data with no grayscale conversion. Brightest-structure rendering retains the color of the voxel with the highest RGB component; transparent rendering composites the sampled RGB values. Black is treated as background by the opacity/threshold transfer function. Each grayscale 8/16/32-bit channel is normalized using its own finite sampled range shared across all time points to preserve relative intensity over time; constant data becomes background. Channels are selected individually with C. The channel’s bright-end ImageJ LUT color is used as a linear tint (falling back to white); arbitrary nonlinear LUT mappings and simultaneous multichannel composite blending are not implemented. RGB stacks retain their original colors. Convert a composite to RGB in Fiji if a flattened color overlay is desired.

The standard **View in VR / AR** command preserves the original X, Y and Z dimensions. The separate **View reduced preview (192 px)** command reduces the longest axis only when explicitly selected and labels the result as reduced. There is no automatic reduction in the standard command. Physical aspect ratio is preserved from calibration. All time points are exported, with the initially selected time point displayed first. RGB stacks retain Z order; grayscale hyperstacks export every channel and every time point. The initially selected C, Z and T are preserved for the initial view. The source image is locked during preparation and is not changed. Original-resolution export visits every source pixel. Only the explicitly selected reduced-preview command uses nearest-neighbor resampling. Grayscale intensities are still normalized to an 8-bit display representation; original spatial resolution does not mean preservation of original 16/32-bit intensity precision. A single image remains a thin plane, not a reconstructed 3D volume. No anatomical orientation is inferred.

Desktop: drag to orbit, scroll to zoom. Controls adjust threshold, opacity and source Z depth. Source Z depth clips at a fixed source Z plane; depending on rotation this can remove structures nearest the viewer. **Show full Z depth** restores the complete stack without resetting its transform. Headset: use left stick X/Y to turn/tilt; right stick Y resizes and right stick X rolls. Hold either controller grip to move/rotate with that wrist. Hold both grips to turn the volume like a ball or move both hands together to reposition it; separating the hands does not resize it. Release either grip to continue with the other hand, and release both to leave it in place. With optional WebXR hand tracking, pinch thumb/index on either or both hands instead of squeezing a controller. Colored markers show tracked grab points and grow when held. Depth clipping remains available in the desktop controls. The C/Z/T, playback and slice-view controls are available on the in-headset panel; threshold/opacity controls remain in the desktop sidebar. Room-relative size is adjustable and is not literal microscopy scale.

## 4D time series

Both RGB and grayscale XYZ+T and XYCZT hyperstacks are supported. The plugin prepares every time point in a temporary folder (no extra user commands), and displays Fiji's progress while doing so. Closing the session window cancels preparation. Preparation time and temporary storage grow with the number of frames, and every channel/time pair is written to disk row by row, avoiding full-volume temporary arrays in Java. Complete volumes are loaded in native-resolution texture blocks; there is no automatic slice fallback.

Desktop controls include a time slider, Previous/Next, Play/Pause, and 1/2/5/10 frame/s playback. Playback loops. Cached time points switch their existing GPU textures without downloading, rescanning or reuploading them. Uncached points wait for a complete volume; the chosen speed is an upper limit dependent on rendering and loading throughput. In the headset, hold the left trigger and tilt the left stick left/right to step through time; holding the stick repeats. Release the trigger to restore rotation. Right-stick zoom and grip manipulation continue to work. Start playback before entering immersion to view a looping series; manually scrubbing pauses it. An in-headset readout shows the displayed time point and calibrated elapsed time when Fiji supplies a positive frame interval. Stopping/losing focus pauses playback.

Full-volume mode automatically prepares nearby upcoming time points, one volume at a time, and retains them in an LRU cache of GPU texture packets. The default **Playback cache** allowance is 512 MiB of extra graphics memory; Off, 256 MiB, 1/2 GiB and explicitly unlimited all-time-point caching are available. If even one extra native volume exceeds the allowance, the readout shows zero cache capacity; it never reduces spatial resolution to fit. When the series fits, the first warm-up prepares all time points and later loops need no image transfer. Longer series retain the closest future points, evicting other inactive packets. Background work is cancelled or adopted when a foreground request supersedes or needs it, and pauses for hidden pages and renderer benchmarking. Background transfer failures leave playback usable with loading on demand. This is a session-only GPU cache, cleared on channel/Z-stream changes and page closure; it does not persist medical/image data on the headset’s disk. Explicit slice-streaming mode keeps the displayed plane and at most two additional decoded planes. Rapid scrubbing cancels obsolete requests and ignores late replies. A failed frame leaves the last successfully displayed frame visible and stops playback. Switching time updates texture data without rebuilding geometry or resetting position, rotation, zoom, threshold, opacity or clipping. Grayscale intensity uses a shared range across the whole series. Time-series files follow the same session-token access boundary and are deleted when the session closes.

## C / Z / T orientation controls

A compact ImageJ-style strip below the desktop image provides C (channel), Z (source slice index) and T (time) sliders. Axes with one value remain visible but disabled. C selects one channel while preserving T and the volume transform. Z moves an XY outline inside the volume; **Slice only** hides volume rendering to inspect that plane alone. The plane follows the volume when rotated. In the standard command each Z slice uses original-resolution data. Only an explicitly reduced-preview session samples Z from a downsampled volume. The whole C/Z/T selection is shown continuously.

In VR/AR a compact panel sits below the forward view. Point a controller at C, Z or T and hold its trigger to drag the slider; arrow regions step one value. Header buttons control playback, toggle slice-only view and switch between **Pin here** / **Follow me**. Pin here fixes both the panel position and orientation in the current XR scene, independent of head motion and volume manipulation. To place it elsewhere, choose Follow me, look towards the new location, then Pin here again. The desktop **Bring VR controls back** button restores following as a recovery option. Pinning survives temporary tracking/focus interruptions within the same session; entering a new VR/AR session starts with the panel following again. This is session-relative placement, not a persistent room anchor across sessions. Supported tracked hands use pinch to activate the ray controls. A source interacting with the panel is excluded from volume grabbing/stick manipulation until released, leaving the other hand available. Existing grip rotation, two-hand manipulation, zoom and trigger/stick time scrolling remain available. The panel initially follows the headset and can be pinned in place. It is never parented to the rotating image.

Every channel/time pair is prepared separately and loaded on demand. Each channel keeps a consistent brightness range across its own time series. This does not establish a common quantitative brightness scale between channels. Changing C cancels obsolete loads, clears the previous channel’s cache, and preserves time, Z, position, rotation and scale. The source Fiji image and selection are not modified. All channels/time points require temporary disk storage while the session is open.

## Verification and limits

Version 0.12 adds real HTTP integration checks for private listener lifecycle, byte-exact two-MiB identity chunks, native ranges, strict origin/CORS handling, exact CSP endpoint permissions, read-only/token/path boundaries, stop-sharing and cleanup. JavaScript checks cover permission gating, automatic reconnection, private-endpoint validation, C/Z/T file routing, source-byte equality, cancelled requests, truncated bodies and visible relay fallback. A native-browser protocol check from the loopback document completed an actual cross-origin private-LAN 8 MiB transfer, verified every byte against the Java fixture and retained the local route without relay fallback. That same-computer check took 36 ms, which is not an over-air Wi-Fi or Quest benchmark. The full 32 MiB synthetic volume also loaded through the private listener in the browser. The separate public-HTTPS-to-local handshake did not complete in the embedded test browser; its page stayed labelled Internet relay. Actual Quest permission handling remains unverified.

Version 0.11 adds deterministic panel placement checks: fixed position and orientation under translated/rotated head poses, controller and hand pin activation, input capture, release without repeated toggling, follow restoration, preservation through temporary hiding and reset for a new session. Physical Quest/PC VR and passthrough placement still need headset verification.

Version 0.10 adds cache ownership/lifetime checks for warm-up without repeated downloads, foreground adoption of pending work, active-volume protection, bounded eviction, cancellation, background failure and channel invalidation. A browser GPU regression renders overlapping dim red front / bright blue back slabs with the production shader: transparent colors respect front-to-back order, reversing the viewpoint reverses occlusion, MIP selects the brighter blue slab from both sides, source-Z clipping and thresholding explicitly exclude the intended slab, full depth restores it, and accelerated/native colors agree exactly. Run `tools/render-visibility-check.html` using a local development server. All seven browser GPU checks passed. Hardware playback rates on Quest remain unverified.

The build targets Java 8 bytecode and uses Fiji's own ImageJ classes. Checks cover grayscale/RGB values and order, channel/time selection, anisotropic calibration, explicit preview sampling, exact 2048 × 2048 original-resolution pixels including one-pixel-wide details, source preservation, packaged libraries, real loopback requests, access boundaries, QR decoding, server stop and temporary-file cleanup. RGB brightest-structure and transparent rendering have been inspected in the desktop browser without console errors. The automatic helper download/checksum, process startup, HTTPS tunnel, and remote synthetic-data fetch also passed an internet integration check.

The updated interaction math has additional deterministic checks for either-hand translation/rotation, two-hand swing/twist, vertical turning, hand-off transitions, overlapping hands, input-source reordering, lost tracking, joystick mapping, simultaneous grip/stick use, zoom limits and pinch hysteresis. Additional checks cover grayscale/RGB Z+T ordering, the selected initial frame/channel, shared intensity range, time calibration, cancellation, frame serving/cleanup, out-of-order replies, bounded caching, playback and trigger-modified scrolling. 5D checks also cover all-channel/time export, manifest contents, channel cache invalidation, late responses across channels, ray/trigger slider capture and panel resource delivery. Additional checks cover HTTP 206/416 slice ranges, 64-bit offsets, device limit decisions, slice-cache invalidation, exact compressed/decoded response lengths, transient transfer failures, retry isolation, cancellation and wrong-range rejection. Acceleration checks cover interpolation halos, block seams, isolated one-voxel features, RGB alpha exclusion, redraw scheduling and 1,200 seeded oblique reference rays in both rendering modes with clipping. The browser loads the interaction module and renders without console errors. The C/Z/T desktop sliders, channel color switching and slice-only view have been checked visually without browser errors. With the updated transfer protocol, the complete synthetic 2048 × 2048 × 40 volume also loaded and rendered through the actual generated public HTTPS link with no fetch or body-length errors in the browser. The synthetic test’s 176 MiB of GPU blocks (including borders) required 5.1 MiB of network download using lossless compression; savings depend on the dataset. An original 2048 × 2048 RGB image and slice streaming were checked in the browser. A complete native 2048 × 2048 × 40 volume (176 MiB including block borders, above the old cutoff) was also loaded across three blocks, rotated in 3D and rendered in maximum-intensity and transparent modes without graphics errors. Actual Quest performance and maximum allocatable volume size remain unverified. The new in-headset panel, updated Quest/PC rotation, bare-hand pinch, passthrough and performance still need hardware acceptance testing. The Swing session window follows Fiji's existing Java look and feel; it is not a separately signed Cocoa application. Native helper execution can still be restricted by managed-device policy.

## Developer build only

End users do not need these commands. The workspace includes a portable JDK, ImageJ compile dependency and ZXing QR library under the parent `.build-tools` folder. From this project:

```sh
python3 tools/build.py --jdk '../.build-tools/jdk-17.0.21+9/Contents/Home' --imagej ../.build-tools/downloads/ij-1.54p.jar
```

This compiles all sources, runs headless image/session checks, bundles ZXing and viewer resources, and creates `target/fiji-vr-0.12.0.jar`. Interaction checks can be run with Node using `node tools/test-interaction.mjs` and `node tools/test-timeline.mjs` and `node tools/test-dimensions.mjs` and `node tools/test-resolution.mjs` and `node tools/test-volume-blocks.mjs` and `node tools/test-transfer.mjs`, `node tools/test-acceleration.mjs` and `node tools/test-ray-skipping.mjs` and `node tools/test-local-transfer.mjs`; they require no npm dependencies. They were run separately using the available JavaScript runtime for this build. The optional `TunnelSmokeTest` exercises download, verification, process startup, HTTPS access and cleanup using fabricated test data only. Maven packaging is also configured. Dependency licenses are bundled under `licenses/`.
